# 0044 行道樹預設顯示，用程式生成的 5 種樹形(InstancedMesh)

日期:2026-11-16
狀態：已實作(未 commit)

## 背景
- 0043:行道樹看不到，是因為 0025 預設隱藏。給 Cooper 兩種樣式:A Tripo 樹模型、B 程式生成 5 種樹形。
- Cooper 2026-11-16:「先用B」。

## 決定
- 預設:`propsModeFromSearch` 預設 `gen`(`?props=tripo` 換回 Tripo);`furnitureShowFromSearch` 樹預設顯示(`?trees=off` 隱藏),機車仍預設不顯示(0025)。
- **效能問題與改法**:原本程式生成模式是每格把每棵樹的幾何接進傢俱網格。樹 4.6 萬棵時 e2e 三次都卡(最長幀 50–67 ms、單格生成最長 41.5 ms)。
  - 改成 5 種樹形各做一個樣板(`treeTemplate`),用 InstancedMesh 畫(沿用 Tripo 的 `PropLayer`,新增 `PropLayer.fromVariants`);每格只帶 [樹形, x, z, 朝向, 大小](`genTreePoses`),大小 = 實測樹高倍率 × 每棵 0.9–1.15 亂數。
  - 程式生成模式的路燈仍接在傢俱網格(1,577 支，量少)。
  - 代價：每棵樹不再有個別的樹冠深淺色(同一樹形同色),只有大小和朝向不同。
- 除錯:`__game.state().propCounts` = 各樹形實際畫出的數量。

## 驗證
- 單元測試 385 項全過(更新：網址預設、gen 模式樹改成擺放資料;新增：擺放資料、5 種樣板)。
- e2e 三次：載入 1.1–1.3 秒;單格生成最長 13.3–16.6 ms(比開樹前還快，因為樹不再接進網格);> 33 ms 卡頓 1 / 0 / 0 幀(最長 49.9 / 33.4 / 17.6 ms)。
- 畫面(拍照腳本，真的瀏覽器視窗):`docs/art/trees-0044/park.jpg`(公園，實測樹)、`taiwan-blvd.jpg`(臺灣大道人行道，層狀 + 球形)、`shizheng.jpg`。

## 踩到的坑
- 用 Claude Code 內建瀏覽器驗證時，面板在背景會被瀏覽器降速(兩幀間隔 1.6 秒),傳送後新格子幾乎不載入，看起來像「樹不見了」。追查後確認資料與程式都正常。之後要看「傳送後的畫面」改用拍照腳本(`tools/shots/spot-shot.mjs`)或先確認面板在前景。

## 放棄的方案
- 維持每格產生樹幾何：效能不行(見上)。
- Tripo 模型(A):Cooper 選 B。
