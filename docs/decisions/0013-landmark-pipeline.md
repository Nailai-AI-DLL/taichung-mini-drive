# 0013 地標管線

- 日期:2026-10-24
- 狀態:**已決定**(純技術;建模工具沿用 Cooper 在 0007 同意的 Blender 腳本)
- 範圍:M1 第 4 項 P0 地標:臺中國家歌劇院、臺中車站(新站與舊站)、臺中市政府臺灣大道市政大樓、臺中市議會

## 1. 決定

| 項目 | 做法 | 檔案 |
|---|---|---|
| 設定 | 地標 id、名稱、對應的 OSM 建築 id、模型路徑、驗收用參考座標 | `data/landmarks/landmarks.json`(手動維護) |
| 建置 | 對應的 OSM 建築不進一般建築，改輸出到 `world.json` 的 `landmarks`。內容是位置(外框面積重心)、高度、相對外框。外框內殘留的一般建築一併挖掉 | `tools/map-build/build.ts` |
| 給 Blender 的外框 | 建置時輸出 `data/landmarks/footprints-<area>.json`。座標用 Blender 慣例:X 東、Y 北，原點為地標形心 | 同上 |
| 建模 | 每棟一支 Blender 腳本，讀外框檔讓量體貼齊 OSM 外框，輸出 `public/models/landmarks/<id>.glb` | `tools/models/landmark_*.py`(之後建立) |
| 座標對齊 | Blender 的 glTF 輸出會把 (x, y, z) 轉成 (x, z, −y)。因此 Blender 的 +Y(北)對應遊戲的 −Z(北),模型不需要額外旋轉 | — |
| 執行端 | 地標依形心分到格子，跟著格子載入。GLB 每個檔只載一次，用 clone 放進場景 | `src/world/chunks.ts`、`src/render/scene.ts` 的 `addLandmark()` |
| 替代量體 | 模型還沒做、或載入失敗時，用外框擠出的量體代替。檔案不存在時不在 console 報錯 | 同上 |
| 碰撞 | 一律用外框擠出的量體，不用模型網格。外框和實際形狀一致，碰撞也比較穩定 | `src/main.ts` |

## 2. 放棄的方案

| 方案 | 理由 |
|---|---|
| 用模型網格當碰撞體 | 曲面多、三角形多，碰撞容易卡住;外框已經足夠準 |
| 用 three.js 在執行期程式生成地標(slop-newyork 的做法) | 0007 已決定地標用 Blender 腳本，倒角、細分曲面比較好做;地標只有 5 棟，檔案很小 |
| 用頂點平均當地標位置 | 臺中車站外框的頂點分布不均，誤差達 17 m,超過 10 m 的驗收門檻。改用面積重心 |

## 3. 驗證

- `tests/unit/landmarks.test.ts`:
  - 5 個地標都有輸出
  - 位置和參考座標的誤差 < 10 m(M1 驗收條件)
  - 外框內沒有殘留的一般建築
  - 每個地標都有碰撞量體
- `tests/unit/buildings.test.ts`:面積重心在頂點分布不均時仍然正確

## 4. 補充(2026-10-31,開始建模後)

| 項目 | 決定 | 理由 |
|---|---|---|
| 高度覆寫 | `landmarks.json` 可加 `height`(公尺)和 `heightSrc`(出處)。有值時取代 OSM 標籤或樓層推估，替代量體和碰撞量體都用這個高度 | OSM 的推估偏差很大：歌劇院 19.2 → 實際 37.7 m,市議會 44.8 → 69.8 m。出處見 `docs/art/landmarks-reference.md` §6、§10 |
| 舊站高度 | 一開始不填 `height`(實際高度 not_stated);Cooper 同意下載文化部保存計畫 PDF 後，改填 21 m(塔尖，經獨立核對，見 `landmarks-reference.md` §11) | 不用推估值覆寫;有出處才填 |
| 布林求解器 | 地標腳本用 `MANIFOLD`(`common.boolean(..., solver='MANIFOLD')`);MINI 腳本維持 `EXACT` | Blender 5.2 的 EXACT 對地標尺度的擠出切割體，會把整個物件切光(連沒倒角的方盒也一樣，切割體本身是封閉網格)。MANIFOLD 結果正確，也支援材質轉移 |
| 開口內的顏色 | 布林用 `material_mode='TRANSFER'`,切出來的面沿用切割體的材質(玻璃、洞窟) | 不用另外選面上色，腳本較短 |
| 模型產生 | `npm run models:landmarks` 依序跑 `tools/models/landmark_*.py`;預覽圖放 `docs/art/landmarks/` | 一個指令重做全部地標 |
| 對位驗證 | `tests/unit/landmark-models.test.ts`:<br>• 外框每個頂點到模型地面頂點的距離 < 3 m<br>• 南北鏡像後要對不上(> 10 m)<br>• 模型最高點等於地標高度<br>還沒做的模型略過<br>• 模型超出外框 < 3 m | 外框是旋轉過的矩形時，看包圍盒分不出鏡像，所以逐點比對 |
| 驗收後補強 | • `landmarks.test.ts` 把有實際高度的地標(現為 5 棟)寫死，不從設定檔讀<br>• 檢查碰撞量體頂端 = 高度 + 女兒牆<br>• 腳本的總高改讀外框檔的 `h`,不在腳本另存一份 | 驗收者發現：拿掉 `height` 後原本的測試會跟著略過 |
| 朝向測試 | 原本：外框是矩形時，模型轉 180° 測試抓不到，只靠腳本的方位參數加上遊戲內截圖。5 棟完成後補上「單側特徵」檢查：用材質顏色找出只在一側的特徵(例如舞台塔、方框、鐘塔帽)。它的形心在指定方位上的投影要大於 3 m;實測是 7–68 m,模型轉 180° 就會變號失敗 | 最終驗收建議;每棟只要一行設定 |

### 放棄的方案

| 方案 | 理由 |
|---|---|
| 換別的建模方式，避開布林運算 | 葫蘆形開口用布林最直接;換成 MANIFOLD 就解決了 |
| 舊站用推估的 14 m / 22 m 覆寫高度 | 不符合「缺料寫 not_stated」;後來改用 PDF 查到的 21 m |

## 5. 補充(2026-10-31,5 棟完成後的驗收)

| 項目 | 決定 | 理由 |
|---|---|---|
| `models:landmarks` 錯誤處理 | 加上 `--python-exit-code 1`;任何一支腳本失敗就印出 log 並 exit 1 | 驗收發現：原本 Blender 腳本出錯時仍回傳 0,錯誤會被吞掉。已用故意寫壞腳本的方式確認會失敗 |
| 對位測試的量法 | 從「外框頂點到模型頂點」改成「外框頂點到模型任何高度的邊，投影到地面」 | 新站的外框會簡化掉共線點，基座也有內縮;OSM 外框多半描的是屋頂輪廓 |
| 新站的殼數 | 參考資料寫「兩片殼」,模型做三片(中段大殼、東段長殼、西段較低的殼) | 外框西段的高架長條如果不加殼，會只剩一段平頂基座;用比 B 再低一階的殼，讓整體從大廳往兩側降下。Cooper 看過預覽後同意 |
| 操作手冊 | `docs/art/landmarks-checklist.md` | 讓之後的人照著步驟改高度、改模型、驗證 |
