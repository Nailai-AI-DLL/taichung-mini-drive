# 0002 技術選型

- 日期:2026-10-11
- 狀態:已決定(純技術路線、可逆,依全域守則由 Claude 自行決定並記錄)
- 相關:`docs/production-plan.md` §6

## 背景

需求指定 three.js。其餘技術(語言、建置工具、物理、地圖建置、建模方式)需選定,以便 M0 開工。

## 決定

| 項目 | 選擇 |
|---|---|
| 語言/建置 | TypeScript + Vite |
| 渲染 | three.js,WebGLRenderer;版本於 M0 開工時鎖定當時最新穩定版 |
| 物理 | Rapier(`@dimforge/rapier3d-compat`),車輛用其射線懸吊控制器,外加自寫街機輔助(轉向隨速衰減、甩尾、防翻、自動扶正) |
| 地圖建置 | 離線 Node 腳本:proj4(投影)、clipper2(道路聯集)、earcut(三角化)、gltf-transform(輸出與 meshopt 壓縮) |
| 座標系 | TWD97 TM2(EPSG:3826)投影後平移到地圖中心;1 單位 = 1 公尺;three.js 的 +X = 東,−Z = 北 |
| 3D 模型 | ~~MINI 與地標以程式碼組合基本幾何體(含倒角)生成~~ → **2026-10-12 改為 Blender 腳本建模,見 0007 第 5 項**(M0 的方塊車仍是程式碼組合) |
| 材質 | 頂點色/純色,不用貼圖 |
| 測試 | Vitest + Playwright |

## 理由

- **TypeScript**:地圖資料結構複雜(道路、路名索引、分塊),型別能減少錯誤。
- **Rapier**:WASM 效能好;有現成車輛控制器;可在 Node 中跑,讓手感指標(加速時間、煞車距離)能寫成自動測試。
- **離線地圖建置**:執行期不做幾何運算,載入快;建置產物可重現。
- **TWD97 TM2**:台灣官方平面座標,公尺單位、變形小,和政府開放資料同座標系,之後疊資料不需再轉換。
- **程式碼建模**:風格一致、可版控、可參數化(例如車色);較弱的模型或其他人只要讀程式碼就能修改或重做,不需要 Blender 技能。

## 放棄的方案

| 方案 | 放棄原因 |
|---|---|
| React Three Fiber | 多一層抽象;遊戲迴圈與物理同步用原生 three.js 更直接 |
| Babylon.js | 需求指定 three.js |
| cannon-es | 維護不活躍,效能不如 Rapier |
| 純運動學假物理(不用物理引擎) | 實作簡單,但碰撞、撞飛小物件、翻車處理都要自己寫,總成本反而高 |
| 執行期即時從 OSM 生成地圖 | 每次載入都要下載與運算,慢且依賴外部 API 可用性 |
| Blender 手工建模為主 | 需要美術技能與外部工具,難以參數化與自動重做;保留為 M2 之後的細修選項 |
| AI 生成 3D 模型 | 風格難統一、面數不可控、授權需逐一確認 |
| 以經緯度直接當座標/Web Mercator | 單位非公尺或有比例變形,物理與距離計算不直觀 |

## 何時重新檢討

- M0 時若 Rapier 車輛控制器手感調不出來 → 改自寫射線懸吊。
- WebGPURenderer 在主要瀏覽器穩定且對本專案有明顯效能好處時 → 評估切換。
