# 日夜切換 / 夜景可行性評估

日期:2026-11-16
問題(Cooper):「目前建築物的做法是否能夠支援日夜切換？假設我要有夜景的話是否方便處理？或是有其他更適合的方式？」
方法：讀程式碼(沒有實作原型)。工作量是推論。

## 結論
**方便。** 現在的做法剛好適合做夜景，不需要換架構。原因有三個:
1. 建築的窗戶是著色器(shader)畫的，不是貼圖或幾何(`src/render/building-material.ts:21-86`)。每扇窗已經有自己的亂數(依欄、樓層、建築種子),夜裡「隨機亮燈的窗戶」只要多加幾行，不增加任何幾何。
2. 全場光照已經集中在一個切換函式(`src/render/scene.ts:40` `setLook`:太陽、天空光、天空漸層、霧),目前用來切新舊光照。多一組「夜晚」參數、或在日夜之間內插，就是日夜切換。
3. 已經有 bloom 光暈後製(`src/render/post.ts:103`,目前強度 0.06、門檻 0.95,白天幾乎看不到)。夜裡調高，窗戶、招牌、車燈就會發光暈。

## 各部分怎麼做(建議做法：全部「假光」,不放大量真光源)
| 項目 | 做法 | 工作量 | 位置 |
|---|---|---|---|
| 天空、霧、太陽、環境光 | 新增 `LOOK_NIGHT` 一組參數(深藍天空、月光很弱、霧變暗);白天 ↔ 夜晚內插 | 小 | `src/config/look.ts`、`scene.ts` `setLook` |
| 建築窗戶亮燈 | 片段著色器加 `uNight`:每扇窗依既有亂數決定亮不亮(例:住宅 30–40%、商辦 60%),亮的加暖黃 / 冷白自發光(emissive),不受光照影響 | 小 | `building-material.ts`(在 `totalEmissiveRadiance` 加) |
| 一樓店面 | 店面深色帶夜裡改成亮的暖色(店家燈光) | 小 | 同上(`shopBand`) |
| 直式招牌 | 招牌板子自發光(霓虹感),夜裡打開 | 小 | 招牌材質 |
| 路燈 | 燈頭自發光 + 地面一圈「光暈貼片」(每支路燈一片半透明圓，加在地上，用 InstancedMesh,一個 draw call) | 中 | 新增；位置沿用 `furniture.lights` |
| 紅綠燈 | 燈號自發光 | 小 | 號誌材質 |
| 其他車輛 | 車頭 / 車尾小方塊自發光(InstancedMesh 多一組) | 小到中 | `src/render/traffic.ts` |
| 玩家 MINI | 頭燈已有自發光(`mini-car.ts:113`);夜裡加一盞真的聚光燈(SpotLight)照路面 | 小 | `mini-car.ts` |
| 陰影 | 夜裡關太陽陰影(反而省效能) | 小 | `scene.ts` |
| 雲 | 雲材質自發光 0.x 要夜裡調暗 | 小 | `clouds.ts:130` |

**整體預估**:第一步(天空 + 窗戶 + 店面 + 招牌 + bloom + 切換鍵)約一批中小工作，和 0037 差不多;第二步(路燈光暈、車燈、紅綠燈)再一批中等工作。

## 效能
- 窗戶、店面、招牌亮燈都在既有著色器 / 材質裡算，不加幾何、不加 draw call。
- 真光源只有玩家頭燈 1 盞;路燈 2,000 多支如果每支放真的點光源，Three.js 傳統渲染器會慢到不能玩，所以用光暈貼片假裝。
- 夜裡可以關掉太陽陰影，比白天還省。

## 其他做法(不建議)
| 做法 | 為什麼不建議 |
|---|---|
| 預先烘焙光照貼圖(lightmap) | 12 萬棟建築是執行時程式生成的，沒辦法事先烘焙;也會讓 map 檔大很多 |
| 換成可以放上千盞真光源的渲染方式(WebGPU 的分塊光照，類似 slop-newyork 的 WebGPU) | 要換渲染器、重寫所有材質，工程很大;卡通畫風用假光暈效果已經夠 |
| 白天、夜晚各做一套建築材質 | 沒必要;同一個著色器加一個 `uNight` 參數就能內插，切換也能做漸變 |

## 需要 Cooper 決定(品味項)
1. 切換方式:按鍵切換(例 N 鍵)、暫停選單切換，或隨時間自動日夜循環(多久一輪)。
2. 夜景風格：亮窗比例、窗燈色(暖黃 / 冷白 / 混合)、招牌要不要像霓虹那樣亮。
3. 要不要有黃昏 / 清晨的過渡色。

## 下一步建議
先做第一步的小樣張(天空 + 窗戶亮燈 + 店面 + 招牌 + bloom,按鍵切換),Cooper 看過畫面再決定風格與第二步。
