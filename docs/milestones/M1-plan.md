## 3. 配色提案:方案丙「真實淡雅」

原則:**色相照真實**(柏油是灰的、草是綠的、台灣建築多為米白 / 淺灰 / 淡磚色、七期大樓多為淺灰與玻璃藍灰),**彩度壓低、明度提高**,整體像蒙上一層柔光。

| 用途 | 色票 | 真實對照 |
|---|---|---|
| 柏油路面 | `#9A9DA1` 霧灰 | 柏油(比真實柏油亮,刻意保留淡雅感;看樣張再調) |
| 標線(M2 起) | `#F4F2EC` 米白 / `#E2D3A0` 淡黃 | 白線、黃線 |
| 人行道 | `#DCD6CB` 暖淺灰 | 人行道地磚 |
| 空地 / 地面 | `#D9D3C3` 淡沙色 | 七期空地、泥土 |
| 草地 / 公園 | `#B9CBA8` 鼠尾草綠 | 草地 |
| 樹(M2 起) | `#97B08F` 淡橄欖綠 | 行道樹 |
| 水道 | `#AFC9CB` 淡灰藍綠 | 柳川、筏子溪 |
| 住宅建築 | `#EFEBE3` 米白 / `#E5DDD0` 淡米 / `#DAD7D0` 淺灰磁磚 / `#E2D2C6` 淡磚 | 透天厝與公寓的磁磚外牆 |
| 商辦大樓 | `#CDD5DB` 玻璃藍灰 / `#D8DADB` 銀灰 / `#E3DCCE` 香檳 | 七期大樓 |
| 屋頂 | `#C7C2B8` 水泥灰 | 頂樓水泥地 |
| 水塔 | `#E8E6E0` 白 / `#C9D2D6` 不鏽鋼 | 頂樓水塔 |
| 天空 | 天頂 `#CFE0EA` → 地平線 `#EAEDEE` | 晴天微霧(地平線偏冷一點,避免和米白建築融在一起) |

- 地標保留自己的真實主色(例:歌劇院的白、舊站房的紅磚),但同樣降低彩度。
- 唯一的深色是你的黑車身。它在淡雅場景裡會是視覺焦點,我認為是好事;車身用帶一點藍的黑(約 `#2A2D33`),不用純黑。
- 這是初稿(實算 HSL 彩度 4–39%、明度 63–94%),實際觀感要看樣張;Cooper 確認的是「整體感覺」,個別色碼我會依樣張微調。

## 4. 模型怎麼做:用 Blender,但是用 Python 腳本建模

**結論:可以用 Blender,而且建議用。** 本機已安裝 Blender 5.2.0 LTS。我已用探針腳本(`tools/models/probe.py`)實測在背景(不開視窗)可以完成:倒角、細分、布林挖洞、純色材質、輸出 GLB、自動算預覽圖;輸出的 GLB 能被本專案的 three.js r186 正確載入(`tools/models/check-glb.mjs`)。探針預覽圖:`docs/art/models/probe.png`(只是測試用的圓角方塊,不是車)。

實測時踩到兩個坑,M1 的共用腳本會內建處理:布林運算後要先清空材質槽,否則顏色會掉;預覽圖讀的顏色欄位和輸出檔不同,兩個都要設。

### 4.1 做法

```
tools/models/
  mini_f55.py        # MINI 建模腳本
  landmark_opera.py  # 每個地標一支腳本
  common.py          # 共用:圓角、配色、材質、輸出
        │  Blender 背景執行(npm run models:build)
        ▼
public/models/*.glb          # 遊戲載入
docs/art/models/*.png        # 自動算圖的預覽圖(正面、側面、3/4 視角),給 Cooper 確認
```

- 用 Blender 的倒角、細分、布林運算做出圓潤可愛的外型。這些在 three.js 裡直接寫很難做好看,這也是改用 Blender 的主要理由。
- 模型全部由腳本產生,可以版控,也可以一鍵重建。之後換配色、調比例,改參數重跑即可。較弱的模型拿到腳本也能修改或重做。
- 我看不到 Blender 視窗,但每次會自動算出預覽圖,我看圖檢查,也把圖給你確認。
- 你如果想在 Blender 裡手動微調也可以,但手調的部分要回寫成腳本參數,否則下次重建會被覆蓋。這部分到時再約定做法。
- 面數預算:MINI ≤ 15,000 三角形、每個地標 ≤ 20,000 三角形。
- 材質只用純色,不用貼圖(延續 0002 的決定)。

### 4.2 各類模型用什麼工具

| 類別 | 工具 | 理由 |
|---|---|---|
| MINI、地標、道具(路燈、水塔、樹) | **Blender 腳本** → GLB | 需要圓潤造型與細節,數量少 |
| 通用建築(約 12,500 棟) | **Node 地圖管線**(沿用 M0) | 數量大、每棟形狀來自 OSM 輪廓,必須程式化;圓角和女兒牆在管線裡做,仍合併成每塊一個網格,不增加 draw calls |
| 道路、綠地、水道 | Node 地圖管線(沿用 M0) | 同上 |

### 4.3 可愛化的手法

- **MINI**:Q 版比例(車身縮短 5–10%、輪子放大約 20%)、圓角車身、大圓燈、白車頂、黑車身。
- **建築**:轉角圓角、屋頂女兒牆、窗戶用淡色橫帶,不做真實窗格;頂樓水塔(台灣特色)在 M2 隨道具加入。
- **地標**:抓最有辨識度的 1–2 個特徵誇大表現,其餘簡化。例:歌劇院的曲面開口、舊站房的紅磚鐘塔。

### 4.4 考慮過但不建議的方案

| 方案 | 不建議的原因 |
|---|---|
| 繼續用 three.js 程式碼組基本幾何體(0002 原決定) | 圓角、曲面難做好看,可愛感不足 |
| Blender 純手工建模 | 無法版控與自動重建;需要美術人力 |
| AI 生成 3D 模型 | 風格難統一、面數不可控、授權要逐一確認 |

已決定(`docs/decisions/0007-m0-feedback.md` 第 5 項),取代 0002 的「以程式碼建模」。
